# 模型资源管理与公开发布

模型中心统一管理六组资源：MOSS Q4、MOSS Q8、MOSS 共用组件、Ditto 原版、Ming-3.0 Q8 语音、Stable Audio 音效。
每组显示安装状态、文件占用、完整大小和公开来源，支持下载修复、SHA-256 校验与删除。
生成之前只检查该功能所需的模型；缺失时弹出下载对话框，不清空草稿或创建失败消息。
下载完成后由用户重新点击生成，避免下载期间修改的作品被自动提交。
新安装默认使用体积更小的 Q4；手动保存的 Q4/Q8 选择及显式环境配置仍然优先。资源页顶部直接设置图像质量和下载源，更改目录留在资源选项菜单。

## 存放与下载

默认根目录为 Qt `AppLocalDataLocation/models`，macOS 通常是
`~/Library/Application Support/MossStudio/MossStudio/models`。
模型中心可切换目录；`MOSS_MODEL_ROOT` 可显式指定测试或离线目录。
旧版 `modelRoot` 设置与源码 `.local/models` 不会被自动采用。

普通版默认“自动选择”：全部 20 个公开网络文件均有 ModelScope 与 Hugging Face 固定来源。两边使用各自的仓库和 revision，同一任务的传输字节与摘要一致，可跨源续传。对这两个来源并发做真实 Range 小样本下载，包含重定向后的文件传输，每源最多 2 MiB、最长 4 秒，按有效吞吐量选择来源；结果按仓库 revision、来源和本机网络短期缓存 10 分钟，网络变化、失败或低速换源时失效。手动选择仍锁定指定提供方；hf-mirror 保留为手动兼容选项，不再参与自动选源。

音效默认使用 Stable Audio 3 Medium F16，配套 SAME-L、conditioner 与共用 T5Gemma 两个文件，共 5,754,163,808 字节。推理调用 `--model medium`，不再回退 Small SFX；App Store 资源包也从同一清单生成。旧 Small 权重不会计入 Medium 就绪状态。

同时下载两个文件；不小于 8 MiB 的 HTTP 文件使用最多四路不重叠 Range（最多八路文件连接）。收到有效的首个 `206 Content-Range` 后才打开其余连接。服务器忽略 Range 时安全退回单连接，不会将重复响应拼入文件。小文件只用一路。

各段的位置写入 `<文件>.part.ranges.json`，先落盘布局再写非连续数据；下载期间每秒和取消/错误退出时更新断点。重新打开或换源时，只补齐各段缺少的字节；旧版连续 `.part` 也可复用。断点绑定文件 SHA-256 和大小，不能误用其他版本；清理残留会同时删除分段记录。稀疏 `.part` 的文件长度不代表已经下载完成，空间预检和完成判断使用分段记录。

每个分段单独计时：首次收到文件数据前允许 60 秒（覆盖连接、TLS、重定向及存储服务准备），收到数据后连续 15 秒无数据则重试；其他分段有进度不会掩盖单段停滞。短测速失败后仍使用首包等待预算尝试实际下载。连接超时或失败时，自动模式切换另一源并续传，每源每文件最多两次失败；手动模式只重试所选来源。首次文件数据到达后，按每个文件全部连接的合计吞吐量取连续 5 秒窗口；低于 1 MB/s（1,000,000 字节/秒）即保留断点并切换下一源，不要求另一源快 50%。若各源都低于门槛，则继续实测较快的一源，30 秒后再评估，避免来回切换。这些是初始策略值，不是对网络速度的保证。最终网络错误包含下载源、实际响应主机、HTTP 状态和已保存字节数，不记录重定向签名参数。

`HTTP 0` 表示没有取得 HTTP 状态码，不能据此判断文件不存在。Windows 上若两入口都超时，应检查实际响应主机的连通性；Hugging Face 与镜像可能最终重定向到同一 CDN。保留 `.part` 及其 `.ranges.json` 可以续传，清理下载残留不会解决网络超时。

Hugging Face 与手动镜像使用相同的固定仓库 revision；ModelScope 使用自己的仓库与固定 revision，所有来源必须匹配同一传输大小和 SHA-256。Warp 两源都下载 `warp_network_ori.onnx`（199,684,283 字节），原始摘要校验通过后原生转换为标准 ONNX opset 20，再核验最终 199,684,279 字节文件的原有 SHA-256；断点绑定原始传输摘要。转换不依赖 Python，安装仍使用原子替换。完整大小及 SHA-256 校验通过后才原子安装；已下载文件在下载/修复时也会重新校验。取消会停止所有在途请求，等待校验或 Apple 本地复制安全退出后释放目录锁。只下载当前功能所需的资源。

下载失败时可展开“查看详情”，查看文件、源、HTTP 状态、已保存大小或安装错误。网络中断保留可续传的 `.part`；完整残留校验通过后可直接安装，修复同大小损坏文件时也会复用。Windows 使用 UTF-16 路径替换已有文件；安装失败保留已校验的下载，关闭占用文件的程序后重试即可，不需清理后重新下载。

`config/models.json` 是下载、安装、删除与模型打包的唯一清单。
目前全部网络负载来自公开 Hugging Face 仓库，完整 revision 与摘要已锁定。
语音使用 Ming-3.0 Q8 单文件 GGUF（1,742,280,896 字节），包括分词器、
说话人编码器与音频编解码器；macOS 使用原生 Metal 推理，输出 44.1 kHz 单声道 WAV。
语音不自动退回 CPU。其他平台的 worker 依次尝试 CUDA、HIP、Vulkan；
没有可用 GPU 后端时提示失败，具体编译支持与初始化原因写入诊断日志。
当前 Ming 原生运行时不提供 Core ML 后端。
开源版和 App Store 版共用该清单；Store 的默认 Apple 下载渠道见
[Apple 资源包说明](apple-model-assets.md)。已有 Hojo/FST 文件不算 Ming 就绪，
本次移除了旧 Hojo 源码及本项目中经哈希确认的旧模型文件；
已生成音频、音色参考录音和对应文本继续保留。
Ming 的原生文本前端不包含原先的中文 FST，日期、金额和缩写需要发音精确时
请写成预期朗读文字。

## 删除与清理

- Q4 和 Q8 分别删除；删除其中一个不会删除另一个或共用组件。
- 共用组件独立删除，确认对话框明确说明会同时影响 Q4 / Q8。
- 删除按清单逐文件处理，包括相应 `.part`；不递归清空目录。
- “清理下载残留”只删除清单中的 `.part`，不影响完整模型。
- 拒绝模型根目录、子目录、文件或残留文件的符号链接。
- 推理、下载或校验期间禁用删除/切换目录；目录锁避免两个模型管理器同时写入。
- 未登记文件、私人 `ditto/`、训练检查点、作品、参考素材均不属于此管理器。
- 已删除的目录可能保留为空目录，下一次下载可以复用。

## 源码与应用发布

`.local/`、`runs/`、模型、训练权重、构建目录、下载残留和私人服务器设置由 Git 忽略。
公开版只支持本地运行；服务器程序、部署与测试脚本、服务器配置均不进入公版源码和 App。

发布前检查：

```sh
python3 scripts/public_release.py audit
python3 scripts/public_release.py source /absolute/path/to/new-public-source
```

源码导出只复制批准的源码目录与公开文档，不读取 `.local`、`runs` 或历史实验目录；
任何符号链接或模型二进制出现在允许的源码目录中都会失败。
该脚本不提交 Git，也不创建或上传任何远程仓库。

默认 `scripts/package.sh` 输出不带模型的客户端。离线包须显式指定公开模型目录：

```sh
./scripts/package.sh --with-models --model-root /absolute/public-models --image-quant Q4_K
```

此时只复制所选 Q4/Q8、共用组件、公开 Ditto、语音和音效的确切文件。
所有文件先通过固定摘要校验；即使把私人权重改名放入公开目录也无法通过打包。
用户可在模型中心选择离线包的 `Contents/Resources/models`，或把它复制到可写模型目录。
不要在只读应用包内下载；默认客户端使用可写用户数据目录。

模型下载改造不等同于源码/依赖的完整开源许可审核或发行签名、公证完成。
项目根目录的源码许可证仍需作者确定，各模型与依赖保留其自身许可。

## Ming 声音设计与朗读选项

声音页可直接输入声音描述和试听文案，生成试听并保存为音色。保存的参考录音
归作品目录下的音色库管理，同时记录描述、文案、Ming 引擎和种子。
保存音色需要三至三十秒的清晰试听；已有音色仍可从录音克隆。

朗读情绪为中性、高兴、悲伤、愤怒、恐惧、厌恶、惊讶。方言可选择普通话、
川渝话或粤语。Ming 的情绪和方言是独立任务，选择川渝话或粤语时，
情绪归为中性且不可叠加；切回普通话后可选择情绪。
选项按作品保存，重新生成会使用新选项，已生成的历史音频保持原样。

## 文字生成形象

形象页的“文字生成形象”使用现有 MOSS 图像模型，默认生成为 768 × 1024
的竖向人像，预览满意后再保存到形象库。保存会复制原图，记录人物描述、
模型摘要、种子与采样步数；生成不会改动当前作品的画布或布局。
首次使用仍通过模型中心提示下载所需的图像组件。保存后的图片可直接用于
现有数字人创作，能否检测到可用人脸仍由数字人处理链实际判断。
