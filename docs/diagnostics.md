# 诊断日志

在「设置 → 通用设置 → 诊断日志」选择「导出日志」，通过系统保存框导出一个
UTF-8 `.log` 文件（每行一个 JSON 事件）。发生推理缓慢或错误后可直接导出，
也可在任务仍运行时导出。导出不发起上传。

## 本地保留

日志位于 Qt `AppLocalDataLocation/diagnostics`，在 Windows 通常位于用户的
Local AppData，在 macOS 位于应用数据目录，商店版使用自身容器。
最多 8 个分段，每个 2 MiB，总计不超过 16 MiB。写入更新使用时间，优先删除
最久未写入的分段；只读导出不刷新使用时间。跨启动保留，进程和线程写入加锁。
短会话继续写入尚未满的分段，不会因多次启动而快速耗尽保留数量。
每条写入立即 flush，磁盘/权限失败不会中断推理；导出头包含记录失败原因。
突然断电时最后一次写入仍可能丢失，不提供原生崩溃转储。

这是独立的诊断缓存，不把作品、输入文件、任务的完整 `engine.log` 或请求 JSON
打包导出，也不删除历史作品。记录参数采用白名单；常见凭证、URL 与用户路径在
写入前脱敏。自由格式的第三方错误消息不是完整的隐私审计，分享前仍可检查文件。

## 记录与判读

- 启动/退出、应用与 Qt 版本、系统内核、CPU 架构和逻辑核心数，以及 Qt 警告/错误。
- 每个 worker 的任务 ID、种类、执行位置、安全参数、阶段耗时、每 10 秒运行状态、
  进度、最终退出码、异常退出、取消和结果验证失败。进度限频，残缺 UTF-8、CR
  进度行与末尾没有换行的错误也会处理。
  阶段耗时按父进程收到输出的时间计算，不是 GPU 同步计时。
- 后端、驱动/设备、内存和性能相关的 worker 输出；如原生结果提供阶段计时，
  保留 `timingsOverlap`，避免把重叠时间相加当成总耗时。
- `gpu=yes` 表示 worker 明确选择 GPU 后端或报告 GPU 计算缓冲区；`no` 表示
  明确 CPU；`mixed` 表示同时观察到 CPU 和 GPU；`unknown` 表示证据不足。
  检测到显卡、列出可用 provider、初始化尝试或包含 “CUDA” 的错误均不算使用证据。
  Core ML 的 CPUAndGPU 配置不证明实际算子放置，保留 `unknown`。
- 所有这些状态都不是显卡利用率采样，`gpuUtilization=not_measured`。本次日志
  不声称提供 GPU 百分比、显存峰值或独立的 CPU 时间。

## 语音策略

移除 Ming 固定 CPU 配置。macOS 构建打开 Metal 并嵌入 shader 库，worker 明确
请求 Metal；其他平台依次尝试 CUDA、HIP、Vulkan。不会使用可能退回 CPU 的
`best` 配置，也不加入 CPU 候选。每次候选失败记录原因；全部失败时返回错误。
该策略对朗读、克隆和声音设计共用的 worker 生效，两种 macOS 发行版共用此实现。
CPU 仍承担文件、音频预处理和调度；没有声称所有操作都在 GPU 上执行。

## 本次验证（2026-10-23）

- 本机编译 `MossStudio`、`moss-voice`、`moss-ditto`，日志、创作页面、文件导出
  三组 CTest 通过；包括短会话重启、容量淘汰、并发写入、脱敏、真实子进程退出、
  尾行错误与分片 UTF-8、GPU 误判防护和无效导出目标。
- Apple M4 Pro 上完成真实语音克隆/朗读与声音设计，输出 44.1 kHz 单声道 WAV，
  FFmpeg 完整解码通过。应用任务报告 `backend=metal`，导出日志包含
  `gpu=yes`、阶段耗时和 `exitCode=0`。不作与旧 CPU 版本的速度提升结论。
- 用仅含 CPU 的旧运行库验证拒绝降级：返回后端不可用错误，退出码 1，不生成音频。
- macOS 原生保存框实际导出成功，默认文件名、Return 保存和 Esc 取消已检查。
  中英文、深浅色均运行检查；960×640 最小窗口使用 Qt offscreen 冒烟，
  未完成原生最小窗口与完整 Tab 焦点循环的专项验收。
- 证据目录为 `.local/evidence/diagnostics-20261023/`，最终原生导出文件
  `diagnostics-final.log` 可解析为 406 条 JSON 记录，包含两次真实任务摘要。
  Windows GPU/驱动和保存框、App Store 沙盒包未实机复验；未发布安装包。
